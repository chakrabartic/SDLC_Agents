# 10 — Data Model & Storage

> **Purpose.** Single source of truth for every entity the PM Agent creates, cites, verifies, approves, or commits. All other spec documents reference these names. Field types use a compact YAML notation; implementation will be Pydantic v2 models (strict mode) generated from these definitions.
>
> **Extends** `PM_Agent_Requirements.md` §12 (Signal, Product Problem, Requirement Draft, Knowledge Article Draft) — every original field is preserved; additions are marked `# +`.

---

## 1. Design rules (apply to every entity)

| # | Rule | Enforced by |
|---|---|---|
| DM-1 | **Facts are `Claim`s.** Any drafted value that asserts something about the world is a `Claim` with ≥ 1 `Citation`. Plain strings are only allowed for identifiers, enums, timestamps and UI labels that carry no factual content. | Verifier V0/V1 ([06](06-grounding-verifier-layer.md)) |
| DM-2 | **Deterministic numbers.** Counts, frequencies, customer lists and dates are computed by code from linked evidence, never generated by an LLM. They are `Claim(kind=aggregate)` and are recomputed by the Verifier. | Verifier V6 |
| DM-3 | **Content addressing.** Every draft, spec, and proposed payload carries `content_sha256` over its canonical JSON (RFC 8785 JCS). Approvals bind to that hash. | HITL Ledger ([07](07-hitl-approval-and-audit-ledger.md)) |
| DM-4 | **Immutability.** Signals are versioned (never updated in place); ledger entries are append-only; drafts are versioned (edit ⇒ new version ⇒ re-verify). | DB grants + hash chain |
| DM-5 | **Redact before store.** No raw secret or un-pseudonymized PII is persisted or shown to a model. Raw payloads that must be kept for provenance are stored encrypted (CMEK) in GCS, readable only by the re-identification service. | Ingestion pipeline + SDP ([06 §5](06-grounding-verifier-layer.md#5-redaction-pii--secrets)) |
| DM-6 | **Memory Bank is not evidence.** Agent Platform Memory Bank stores PM preferences only; it can never be the target of a `Citation`. | Verifier V2 (resolver only accepts `evidence.*` ids) |
| DM-7 | **Config is data.** Templates, readiness checklist, DLS library binding, connector set, thresholds and policies are versioned rows in `config.*` (NFR-9). Every output records the config versions it used. | Loader + `VerificationReport.policy_versions` |

## 2. Evidence entities

### 2.1 `Signal` — canonical, normalized record (one per source record *version*)

```yaml
Signal:
  signal_id: str                 # "sig_" + ULID
  source_system: enum            # ado | servicenow | pagerduty | email | onedrive | pm_input | kb | figma
                                 # extension: teams | uservoice | usersnap | csm | esm | myelite | grafana
  source_record_id: str          # e.g. "2830205" (ADO), "11107122" (PD), "CS2461006" (SNOW)
  source_version: str            # + ADO rev, SNOW sys_mod_count, PD log-entry id, Graph changeKey, etag
  record_type: enum              # + incident | request | case | work_item | comment | journal_note
                                 #   email_message | document | tracker_row | pm_answer | kb_article
  parent_signal_id: str|null     # + comment/note → its incident/work item; email → thread root
  permalink: url                 # resolvable deep link (required; ingestion rejects records without one)
  captured_utc: datetime         # when the source says it happened
  author: PersonRef              # + pseudonymized (see §6); never a raw name/email
  customer: {name: str|null, region: str|null}   # business entity, not PII (e.g. "CVX", "NAM")
  product: str|null              # resolved via config.product_aliases (e.g. "DrillOps", "Lumi for Ops")
  title: str|null                # + redacted
  raw_text: str                  # REDACTED + normalized text (the only text models ever see)
  artifacts: [ArtifactHandle]    # large payloads/attachments stored by reference (IR4)
  cross_refs: [CrossRef]         # + deterministic IDs found in text: ADO ids, PD #, INC/CS numbers, URLs
  signal_type_hint: enum         # feature_request | workflow_problem | knowledge_gap | defect | enhancement | unknown
  language: str                  # + BCP-47
  sensitivity: {purview_label: str|null, legal_tags: [str]}   # + NFR-11 (WODF legal tags, Purview labels)
  redaction: {policy_version: str, findings: {INFO_TYPE: int}} # + counts only, never values
  ingestion: {run_id: str, connector: str, connector_version: str, fetched_utc: datetime}  # +
  provenance_hash: str           # sha256(source_system|source_record_id|source_version|sha256(raw_text))
  status: enum                   # + active | superseded | tombstoned (source deleted / access revoked)
```

`CrossRef = {system, record_id, pattern_id, char_span}` — produced by versioned regex detectors (e.g. `_workitems/edit/(\d+)`, `PD #(\d+)`, `\bCS\d{7}\b`, `\bINC\d{7}\b`). Cross-refs create **hard links** in correlation (strongest signal of "same problem").

### 2.2 `EvidenceChunk` — the citable unit

```yaml
EvidenceChunk:
  evidence_id: str               # "ev_" + ULID — the ONLY id a Citation may reference
  signal_id: str
  seq: int                       # chunk order within the signal
  text: str                      # slice of Signal.raw_text (redacted)
  char_start: int                # offsets into Signal.raw_text
  char_end: int
  text_sha256: str
  embedding: vector(3072|768)    # dimension fixed per config.embedding_model (see ADR-008)
  tsv: tsvector                  # lexical index for hybrid retrieval
```

Chunking: semantic-boundary aware (paragraph / comment / email-part), 200–600 tokens, 15 % overlap; comment threads keep one comment per chunk so author attribution survives.

### 2.3 `Citation` and `Claim` — the grounding contract (R6)

```yaml
Citation:
  evidence_id: str               # must resolve in evidence.chunks (status=active)
  signal_id: str
  source_system: enum
  source_record_id: str
  permalink: url                 # copied from Signal at citation time; re-checked by Verifier V2
  span: {start: int, end: int}   # offsets within EvidenceChunk.text
  quote: str                     # == chunk.text[start:end]; ≤ 400 chars
  quote_sha256: str

Claim:
  claim_id: str                  # "clm_" + ULID
  text: str                      # ONE atomic statement
  kind: enum                     # fact | classification | aggregate | pm_judgment | inference | procedural
  citations: [Citation]          # ≥1 for fact/classification/aggregate/pm_judgment; 0 allowed only for
                                 # inference (flagged, quarantined) and procedural (no factual atoms)
  atoms: [str]                   # deterministic extraction: numbers, ids, dates, versions, proper nouns
  confidence: float|null         # model self-report; informational only, never used for gating
  verification: {status: pending|pass|fail, failed_checks: [str]}
```

| `kind` | Meaning | Citation rule | Where allowed |
|---|---|---|---|
| `fact` | Statement about source content | ≥ 1, span-exact, entailed | Any field |
| `classification` | Label (e.g. *defect*) + rationale | ≥ 1 to the evidence that justifies the label | Classification fields |
| `aggregate` | Count/list computed by code | One citation per counted item | Impact, frequency, customers |
| `pm_judgment` | PM-supplied answer/decision | ≥ 1 to a `pm_input` signal (ledger-backed) | Any field |
| `inference` | Agent reasoning not directly stated | none — **quarantined** to `inferred_fields`, visibly flagged, never committed unless the PM converts it to `pm_judgment` | `inferred_fields` only |
| `procedural` | Status/UX text ("Draft ready for review") | none, but must contain **zero atoms** | Chat/UI only |

### 2.4 `PersonRef` — pseudonymous person reference

```yaml
PersonRef:
  token: str                     # deterministic SDP surrogate, e.g. "PERSON_9F2C1A"
  role_hint: str|null            # derived from directory/team metadata, e.g. "L2 Support", "RTDS SRE"
  org_unit: str|null
```

Real names are revealed only in the PM Workbench to authorized users via the re-identification service ([08 §6](08-security-identity-and-governance.md#6-data-protection)); they never enter prompts, drafts bound for external systems, or logs.

## 3. Problem & analysis entities

### 3.1 `ProductProblem` (extends §12.2)

```yaml
ProductProblem:
  problem_id: str                # "prb_" + ULID
  version: int                   # +
  title: Claim                   # drafted label — cited like any other drafted field
  product_line: str              # +
  classification: Claim          # kind=classification; label ∈ {feature_request, workflow_problem,
                                 #   knowledge_gap, defect, enhancement}
  classification_confidence: enum  # + high | medium | low  (low ⇒ PM confirmation required, §13)
  linked_signals: [SignalLink]   # {signal_id, link_type: hard_ref|semantic|pm_confirmed, score, linked_by}
  affected_customers: Claim      # kind=aggregate (code-computed from linked signals)
  affected_regions: Claim        # + kind=aggregate
  request_frequency: Claim       # kind=aggregate: distinct requesting signals / customers / 90-day window
  impact: {business: [Claim], customer: [Claim]}
  duplicates: [DuplicateCandidate]   # {ref, system, similarity, method, decision: pending|linked|merged|distinct}
  readiness: ReadinessAssessment
  open_questions: [ClarifyingQuestion]
  sources_unavailable: [str]     # + IR3: connectors that failed during the last refresh ("partial" banner)
  owner_pm: PersonRef            # +
  status: enum                   # new | gathering | ready_for_draft | drafted | pending_approval
                                 # | approved | committed | closed      (+ pending_approval, closed)
  content_sha256: str            # +
```

### 3.2 `ReadinessAssessment` and `ClarifyingQuestion` (FR-A5, FR-A6)

```yaml
ReadinessAssessment:
  checklist_id: str              # config.readiness_checklists (default "slb-readiness-v1")
  items:                         # one per checklist item
    - item: enum                 # who_affected | current_vs_desired_workflow | should_do_should_not
                                 # | acceptance_criteria | edge_cases | dependencies_constraints
      status: enum               # present | partial | missing
      claims: [Claim]            # evidence supporting "present/partial"; empty ⇒ missing
      gap: str|null              # what exactly is missing (procedural text, no atoms)
      question_ids: [str]

ClarifyingQuestion:
  question_id: str
  checklist_item: enum
  text: str
  why_asked: [Claim]             # cites the evidence that shows the gap/ambiguity (or "no evidence found")
  suggested_respondents: [{person: PersonRef, basis: Claim}]  # e.g. authored the resolution comment
  status: enum                   # open | answered | dismissed
  answer_signal_id: str|null     # PM answer becomes a pm_input Signal → citable
```

### 3.3 `InvestigationPack` (FR-C1–C3, C5)

```yaml
InvestigationPack:
  pack_id: str
  trigger_signal_id: str
  related: [SignalLink]                       # cross-system correlation result
  scale: {signals: Claim, customers: Claim, regions: Claim}   # aggregates
  prior_resolutions: [{ref: str, summary: Claim}]   # KB/ADO/SNOW matches surfaced first (FR-C5)
  timeline: [{at: datetime, event: Claim}]
  suggested_engagements: [{team_or_role: str, basis: Claim}]
  outcome: Claim|null                         # classification ∈ {workaround, workflow_clarification,
                                              #   defect, non_defect} — PM confirms
  next_step: enum|null                        # draft_bug | draft_enhancement | draft_kb | none
```

## 4. Draft entities (everything that can become a proposed write)

### 4.1 `RequirementDraft` (extends §12.3)

```yaml
RequirementDraft:
  requirement_id: str            # "draft-req-" + ULID
  version: int                   # +
  problem_id: str
  template: str                  # "slb-ado-requirement-v1" | "slb-initiative-v1" (see §4.2)
  work_item_type: str            # + "Requirement" | "Initiative" (SLB custom process — confirm, Q-04)
  fields:                        # each value is a DraftField
    summary: DraftField
    user_workflow: DraftField
    desired_outcome: DraftField
    in_scope: DraftField
    out_of_scope: DraftField
    acceptance_criteria: DraftField
    edge_cases: DraftField
    dependencies: DraftField
    technical_constraints: DraftField
  citations: [FieldCitation]     # §12.3 compatibility view, derived from DraftField claims
  feasibility: FeasibilityAssessment
  inferred_fields: [str]         # names of fields containing quarantined inference claims
  ado_mapping: {str: str}        # + template field → ADO reference name (config, e.g. System.Title)
  prd_markdown_ref: ArtifactHandle   # + rendered from claims; never authored free-form
  near_duplicates: [DuplicateCandidate]   # + G3 gate result
  content_sha256: str            # +
  verification_report_id: str|null        # +
  approval: {state: pending|approved|rejected|changes_requested, approver: PersonRef|null, utc: datetime|null}

DraftField:
  status: enum                   # populated | partial | missing | inferred
  claims: [Claim]
```

`FeasibilityAssessment = {verdict: supportable|constraints|blocked, claims: [Claim], affected_components: [Claim], advisory: true, engineering_signoff_required: true}` (FR-A8; GOV3 — the agent advises, Engineering decides). `ImplementationPlanDraft` (FR-A9) reuses the same shape with ordered `steps: [DraftField]`.

### 4.2 SLB templates (derived from the corpus — **SLB to confirm canonical versions**, Q-04)

Source: `DrillOps-Workflow-Slowly Progressed/Extended Delivery Effort/In-depth_Requirement Description - Portfolio & Engineering.docx` (section headings, roles in parentheses) and `Work Items List.csv` (work-item hierarchy *Initiative → Requirement*, title prefix convention `[Component][Customer][Theme] As <persona>, I need … so that …`).

| `slb-initiative-v1` section (owner per SLB template) | Draft field | Min. evidence |
|---|---|---|
| Business driver description (Initiative Creator) | `business_driver` | customer/business signals |
| User(s) or persona (Initiative Creator) | `personas` | signals naming roles |
| Which deployment, which customer, when (Initiative Creator) | `deployment_customer_timing` | aggregates + pm_judgment |
| Expected business goals by phase/milestone (Initiative Creator) | `business_goals` | pm_judgment |
| High-level business acceptance criteria (Creator → PO review) | `business_acceptance_criteria` | signals/pm_judgment |
| Business scenario / expected user workflows (Creator → PO) | `user_workflow` | signals |
| Known business constraints / conflicts (Creator → PO) | `business_constraints` | signals |
| Applications involved upstream/downstream (Creator → PO) | `applications_involved` | signals/docs |
| Requirements per milestone/phase (Product Owner) | `requirements_by_phase` | links to Requirement drafts |
| Initiative/workstream roadmap (PO / Workstream Prime) | `roadmap` | trackers (read-only) |
| Architecture definition (Architect, optional) | `architecture_definition` | **advisory only** |
| Known technical constraints (Architect, optional) | `technical_constraints` | docs/ADO |
| Engineering acceptance criteria (Architect + PO, optional) | `engineering_acceptance_criteria` | **advisory only** |

`slb-ado-requirement-v1` = the nine §12.3 fields above, mapped to ADO fields via `config.ado_field_map` (defaults: `summary→System.Title`, rendered PRD body→`System.Description`, `acceptance_criteria→Microsoft.VSTS.Common.AcceptanceCriteria`; customer/product tags→`System.Tags`; remaining fields as sections inside the description until SLB confirms custom fields).

### 4.3 `PrototypeBrief`, `PrototypeSpec`, `ValidationPackage` (FR-B1–B5)

```yaml
PrototypeBrief:                  # spec-to-experience translation (FR-B1)
  brief_id: str
  requirement_id: str            # must reference an APPROVED requirement
  workflow_steps: [Claim]        # each cites requirement fields (which cite evidence)
  interaction_model: [Claim]
  states_and_edge_cases: [Claim]

PrototypeSpec:                   # the ONLY input the Figma renderer accepts (ADR-006)
  spec_id: str
  brief_id: str
  dls_library: {file_key: str, published_version: str}   # SLB DLS library snapshot used
  screens:
    - name: str
      frame: {width: int, height: int, layout: AutoLayout}
      nodes: [SpecNode]          # tree; leaf = component instance or text bound to a Claim
  new_patterns:                  # FR-B3: every non-DLS element must be justified
    - name: str
      justification: [Claim]     # why no existing component suffices
      nearest_candidates: [{component_key: str, why_insufficient: str}]
  reuse_ratio: float             # instances of DLS components / all components (target ≥ 0.9, config)
  content_sha256: str

SpecNode:
  kind: enum                     # instance | text | frame
  component_key: str|null        # must exist in dls_catalog snapshot (Verifier V9-DLS)
  variant_props: {str: str}
  text_claim_id: str|null        # visible copy comes from cited claims or approved placeholders
  children: [SpecNode]

ValidationPackage:               # FR-B4
  package_id: str
  spec_id: str
  figma_refs: {file_key: str, node_ids: [str]}
  screenshots: [ArtifactHandle]
  narrative: [Claim]
  validation_questions: [str]
  audience: enum                 # internal_showcase | early_client_validation
  feedback: [Signal]             # FR-B5: Figma FILE_COMMENT webhooks + PM notes → pm_input/figma signals
```

## 5. Traceability & roadmap entities (FR-C6, C7)

```yaml
TraceLink:
  link_id: str
  from_ref: EntityRef            # {type, id}
  to_ref: EntityRef
  link_type: enum                # customer_reported | signal_of | bug_for | discussed_in | resolved_by
                                 # | captured_as_knowledge | specified_by | planned_in | decided_by
  basis: [Claim]                 # why the link exists
  created_by: enum               # agent | pm
  status: enum                   # proposed | confirmed | rejected
```

The evidence chain *Customer → Problem → Bug → Engineering discussion → Resolution → Requirement → Roadmap decision* is a path query over `TraceLink` (AC7). `RoadmapItem` mirrors ADO Initiatives and OneDrive tracker rows (read-only). A **roadmap decision is always a PM act** recorded as a `DECISION_RECORDED` ledger entry; the agent may only *propose* trace links to it.

## 6. HITL entities (summarized — full protocol in [07](07-hitl-approval-and-audit-ledger.md))

| Entity | Key fields |
|---|---|
| `VerificationReport` | `report_id, subject_ref, subject_sha256, verifier_version, policy_versions{}, checks[{id, status, details}], overall: PASS|FAIL|NEEDS_PM_DECISION, blocked_claim_ids[], kms_signature` |
| `ProposedAction` | `action_id, action_type, target{system, scope}, payload, payload_sha256, draft_ref, verification_report_id, risk_flags[], proposed_by{agent_identity, session_id, trace_id}, expires_utc, status` |
| `ApprovalDecision` | `decision_id, action_id, decision: approve|reject|request_changes, approver{sub, email, idp, groups}, comment, decided_utc, authn_assertion_sha256` |
| `ApprovalToken` | JWS (ES256, Cloud KMS): `iss, sub, aud, jti, iat, exp, act, pah, tgt, scp, vrf` |
| `LedgerEntry` | `seq, entry_id, entry_type, subject_refs[], actor{type, id}, payload(redacted), prev_hash, entry_hash, recorded_utc, trace_id` |

`action_type` enum (closed list, deny-by-default): `ADO_CREATE_WORK_ITEM`, `ADO_ADD_LINKS`, `KB_PUBLISH_ARTICLE`, `FIGMA_RENDER_PROTOTYPE`, `FIGMA_POST_COMMENT`, `PROTOTYPE_RELEASE_INTERNAL`, `OUTREACH_SEND_INTERNAL`, `ROADMAP_TRACE_LINK`.

## 7. Physical storage

| Store | Contents | Why this store | Protection |
|---|---|---|---|
| **AlloyDB for PostgreSQL** (AlloyDB AI) db `pm_agent` | schemas `evidence` (signals, chunks + `vector` + ScaNN index + `tsvector`), `problem`, `drafts` (JSONB, versioned), `hitl` (actions, decisions, token `jti` registry, **ledger**), `trace`, `config` | Transactional (single-use token consumption, versioning), hybrid vector + lexical retrieval in one engine, Postgres grants for append-only ledger | CMEK, private IP only (PSC), IAM DB auth, per-service DB roles; ledger role = `INSERT, SELECT` only |
| **Cloud Storage** `pm-agent-artifacts-<env>` | Raw (encrypted) source payloads, attachments, PRD renders, prototype screenshots — referenced by `ArtifactHandle` | Large payloads by handle (IR4) | CMEK, uniform bucket-level access, VPC-SC |
| **Cloud Storage** `pm-agent-ledger-exports-<env>` | Daily signed ledger segment exports | WORM evidence for audits | **Bucket Lock** retention policy (locked) |
| **Cloud Logging** bucket `pm-agent-ledger` | Mirror of every ledger entry + periodic chain-head anchors | Immutable once retention is **locked**; SQL via Log Analytics linked BigQuery dataset | Locked retention, CMEK |
| **BigQuery** `pm_agent_analytics` | Signals/problems facts, trace links, KPI tables (§3.3 metrics), eval results | Trend & roadmap analytics (FR-C7), dashboards (NFR-10) | Column-level policy tags for customer fields |
| **Pub/Sub** | `signal-change-hints`, `signal-ingested`, `problem-updated`, `ledger-events` (+ DLQs) | Decoupled continuous ingestion and UI refresh | CMEK, VPC-SC |
| **Agent Platform Sessions** | Conversation state per PM session | Managed, regional (us-central1) | Platform-managed |
| **Agent Platform Memory Bank** | PM preferences (templates, product focus, tone) — **non-evidential** (DM-6) | Personalization across sessions | Scoped per PM user id |
| **Secret Manager** | Third-party credentials not brokered by Agent Identity Auth Manager | Rotation, audit | CMEK, per-secret IAM |
| **Cloud KMS** | `approval-token-signer` (EC P-256), `verifier-report-signer`, SDP pseudonymization wrapping key, CMEK keys | HSM-backed signing; LLM-inaccessible | Separate key ring per env; signer use restricted to `mcp-ledger` / `mcp-verifier` SAs |

### 7.1 Retention & classification (defaults — confirm with SLB, Q-09)

| Data | Classification | Retention |
|---|---|---|
| Redacted signals & chunks | Confidential – business | 3 years rolling (configurable per source) |
| Encrypted raw payloads (GCS) | Restricted | 180 days, then delete (provenance keeps hash + permalink) |
| Drafts & specs | Confidential – business | Life of problem + 2 years |
| Ledger + exports | Restricted – audit | 7 years (locked) |
| Session transcripts | Confidential | 90 days |
| Eval datasets (sanitized) | Internal | Versioned in repo; no raw corpus in Git |
